# Verdict JSON (`reports/<id>.json`), schema version 1

Every audit published from now on has three files in `reports/`:

| File | For | Written by |
|---|---|---|
| `<id>.md` | People: the full report | Reviewer LLM (`work/<id>/report.md`), copied by `host/publish_report.py` |
| `<id>.json` | Machines: verdict, findings, dates (this document) | Reviewer LLM (`work/<id>/report.json`), validated and copied by `host/publish_report.py` |
| `<id>.sarif` | Code-scanning tools ([SARIF 2.1.0](https://docs.oasis-open.org/sarif/sarif/v2.1.0/sarif-v2.1.0.html)) | Generated by `host/publish_report.py` from the validated JSON |

The reviewer only ever writes inside `work/<id>/`. `host/publish_report.py` (stdlib only) is the one thing that writes
`reports/`; it refuses to publish anything (Markdown included) when `report.json` breaks a rule below, and leaves
everything in `work/<id>/` for a human. Reports published before this schema existed have Markdown only; they are
tool output and are not regenerated.

## Example
```json
{
  "schema": "plugin-audit/verdict",
  "schema_version": 1,
  "audit_id": "example-tool-1a2b3c4",
  "tool": "owner/example-tool",
  "commit": "1a2b3c4d5e6f708192a3b4c5d6e7f8091a2b3c4d",
  "verdict": "USE WITH PRECAUTIONS",
  "summary": "No malware. Telemetry is on by default and the MCP server is fetched unpinned with npx.",
  "dates": {"scanned": "2026-11-20T09:15:02Z", "reviewed": "2026-11-20"},
  "findings": [
    {
      "id": "F1",
      "severity": "medium",
      "category": "telemetry",
      "title": "Usage analytics sent to a third party by default",
      "detail": "Every command reports its name and duration; opt out with EXAMPLE_TELEMETRY=0.",
      "evidence": "lib/telemetry.js:14 posts to analytics.example.net; run phase: DNS query analytics.example.net refused",
      "location": {"path": "lib/telemetry.js", "line": 14},
      "matches_stated_purpose": false
    }
  ],
  "precautions": ["Set EXAMPLE_TELEMETRY=0", "Pin the MCP package to the audited version"],
  "not_covered": ["The Docker image (no Docker in the VM)"]
}
```

## Fields
Unknown fields are refused at every level (a new field means a new `schema_version`).

| Field | Type | Required | Rule |
|---|---|---|---|
| `schema` | string | yes | Exactly `plugin-audit/verdict` |
| `schema_version` | integer | yes | `1` |
| `audit_id` | string | yes | The audit ID, `<name>-<sha7>` (must be the one being published) |
| `tool` | string | yes | The target label from `work/<id>/meta.json`: `owner/repo`, the git URL, or `local:<folder>` |
| `commit` | string | yes | 40 lowercase hex characters; must equal `meta.json`'s `commit` (a content hash for local folders) |
| `verdict` | string | yes | `SAFE TO USE`, `USE WITH PRECAUTIONS` or `DO NOT USE`; must match the index row and the report title |
| `summary` | string | yes | The bottom line, 1-1500 characters |
| `dates.scanned` | string | yes | Must equal `meta.json`'s `scanned_at` (UTC, `YYYY-MM-DDTHH:MM:SSZ`) |
| `dates.reviewed` | string | yes | `YYYY-MM-DD`, not before the scan date and not after tomorrow (UTC) |
| `findings` | array | yes | 0-200 finding objects (below); may be empty |
| `precautions` | array of strings | no | Up to 50, each 1-500 characters |
| `not_covered` | array of strings | no | Up to 50, each 1-500 characters |

A finding:

| Field | Type | Required | Rule |
|---|---|---|---|
| `id` | string | yes | Unique in the file, letters/digits/`-`/`_`, starting with a letter, max 32 (`F1`, `F2`, ...) |
| `severity` | string | yes | `critical`, `high`, `medium`, `low` or `info` |
| `title` | string | yes | One line, 1-200 characters |
| `evidence` | string | yes | `file:line` or a log line, 1-1000 characters |
| `category` | string | no | Lowercase slug, max 40 (`telemetry`, `supply-chain`, `mcp`, `credential-access`, ...) |
| `detail` | string | no | What it does and why it matters, max 2000 characters |
| `location` | object | no | `{"path": ..., "line": ...}`: `path` relative to the target's root (as under `work/<id>/src/`, without `src/`), must exist there; `line` optional, integer ≥ 1 |
| `matches_stated_purpose` | boolean | no | The reviewer's yes/no |

## Checks beyond the field rules
- Valid UTF-8 JSON object, at most 1 MB, no duplicate keys.
- Text fields carry no control characters (newlines and tabs are allowed in `summary`, `detail` and `evidence` only)
  and no invisible or text-hiding characters (ANSI escape, bidi controls, zero-width characters, Unicode tags).
- The verdict agrees with the findings: `SAFE TO USE` has no `critical` or `high` finding; `DO NOT USE` has at least
  one.
- The same secret and host-path check as the Markdown report, run on the decoded text (so `\u` escapes cannot hide a
  token).

## SARIF mapping
One run per file, tool `plugin-audit`; `versionControlProvenance` names the repository and commit (not for local
folders); run `properties` carry `verdict`, `auditId`, `tool`, `commit`, `reviewed` and `schemaVersion`.

| Verdict JSON | SARIF |
|---|---|
| `category` (or `finding`) | rule `plugin-audit/<category>`, with `security-severity` from the most severe finding in it |
| `severity` | `level`: critical/high → `error`, medium → `warning`, low/info → `note`; also `properties.severity` |
| `title`, `evidence` | `message.text` |
| `location` | `physicalLocation` relative to `SRCROOT` (the audited repository's root) |
| `id`, `matches_stated_purpose` | `properties.findingId`, `properties.matchesStatedPurpose` |

Findings without a `location` (for example runtime behaviour) have no `locations`; this is valid SARIF, but GitHub
code scanning only shows results that have a location.

## Versioning
`schema_version` changes whenever a field is added, removed or redefined. The publisher accepts exactly the versions
it knows; consumers should check `schema` and `schema_version` before reading anything else.
