# larrynovsky/larry-health-os — USE WITH PRECAUTIONS
Commit `e5bb6832d11b74e39941ccbe51cdbe4b4a286e75` · audited 2026-11-09 · Self-hosted personal health system: a Python monolith (Telegram bot, local FastAPI dashboard, scheduler, about 25 jobs) that collects labs, doctors' letters, Oura/Apple Health/Withings data and genome files into a local SQLite database and sends them to an LLM for daily briefs. The documented install is a Docker image prebuilt on GHCR.

**Bottom line:** No malware, hidden instructions, obfuscation or undisclosed phone-home were found. The scanners' "high" hits are false positives: an agent *deny* list, Telegram bot API calls, and the author's own launchd/Studio tooling. The real risk is the design. **Your full medical record, lab scans and doctors' letters are sent to the LLM provider** (Anthropic by default). Genome rsIDs go to myvariant/EBI/NCBI/PGS, and coordinates go to weather/geocoding services. All of this is disclosed in the README. The installer follows `releases/latest`, and the image you run is **not built from the audited source**. **The VM run only did `pip install -r requirements.txt`.** No bot, dashboard, job or installer ran, so this verdict rests on code review.

## What it can touch
- **Files:** `~/health-docker/` (compose.yaml, `.env`, `secrets/` with mode 700/600 holding the Telegram token, chat id and LLM key). Docker volumes hold the database and logs. The secrets are mounted read-only into the containers.
- **Network (by design, disclosed):** the LLM provider (`api.anthropic.com` / `api.openai.com` / `generativelanguage.googleapis.com`), `api.telegram.org`, Oura/Withings/Google Calendar (when connected), PubMed `eutils.ncbi.nlm.nih.gov`, `myvariant.info`, `www.ebi.ac.uk`, `www.pgscatalog.org`, `ftp.ebi.ac.uk`, Open-Meteo/WAQI/Nominatim/BigDataCloud (approximate coordinates), `api.github.com` (daily release check, WellAlly prompt check). Optional: `api.typesafe.ai` (only with a key), healthchecks.io, Google Drive/Yandex Disk/Dropbox/OneDrive (only links you send; allowlisted).
- **Developer bug reports:** `/bug` in the bot sends a report to the author's receiver (URL baked into release images). Only you can trigger it. The schema is allowlist-only: enums, code locations and exception types, no free text.
- **Listening ports:** dashboard `127.0.0.1:8001` (no password), phone ingest `127.0.0.1:8011` (opt-in `--lan-ingest` binds `0.0.0.0`, token-protected, write-only).
- **Persistence:** containers with `restart`; on macOS with Colima profile `health`, the installer adds LaunchAgent `com.larry.health.colima` (starts Colima at login). Disclosed.
- **Credentials/agent config:** nothing reads your `~/.ssh`, Keychain, browser data or `~/.claude`. Its only Claude use is the author's own `night_repair.py` (see Findings).

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Install (auto scenario):** `uv venv` + `uv pip install -r requirements.txt`. Hosts: `pypi.org`, `files.pythonhosted.org` only. One C extension compiled with gcc. No suspicious execs, 0 decoy reads, 0 refused hosts, no direct egress.
- **Run:** only `cat` of the two agent config files the scenario planted. **No project code ran.**
- **Result:** no persistence, no leftover processes, no changes outside the project except the two planted configs. This shows the pinned dependencies install cleanly. It says **nothing about the tool's own behaviour**.

## How to use it safely
1. **Decide on the data flow first.** Everything you upload, including relatives' records, goes to your LLM provider under its API terms. Genome IDs go to public annotation services. If that is not acceptable, don't use it.
2. **Pin the version.** Download `install.sh`, `compose.yaml` and `health.env` from a specific release tag rather than `latest`. Pin the image by digest (`image: ghcr.io/larrynovsky/larry-health-os@sha256:…`). Don't re-run `install.sh` blindly to "update"; re-audit first. For most assurance, build the image yourself from this commit (`docs/how-to/install_docker.en.md`).
3. Use a **dedicated** Telegram bot and a **dedicated, spend-limited** LLM API key.
4. Keep the dashboard on `127.0.0.1`. Leave `--lan-ingest` off unless you need Apple Health push, and then only on a trusted network. Don't create `~/.health_mcp` (public MCP endpoint) unless you accept an internet-facing server.
5. Only send it documents from sources you trust, and read every confirmation card before accepting it into your record.
6. Don't run the author's personal tooling: `scripts/install_hooks.sh`, `night_repair.py`, the launchd templates, `scripts/git-hooks/*`.
7. Use `/bug` only if you're fine sending code locations and error types to the author.

## Not covered
- **No runtime coverage of the tool.** The auto scenario installed `requirements.txt` and stopped. Not exercised: `scripts/install.sh` (needs Docker, which the VM lacks), the GHCR image, `scripts/install.py --files-only`, the bot, the dashboard and phone ingest servers, the scheduler and jobs, `health_mcp.py`, link fetching, and the bug report channel. A useful re-run: install.sh `uv venv .venv && uv pip install … -r requirements.txt`; run.sh `install.py --apply --non-interactive --files-only --data-dir ~/work/d --secrets-dir ~/work/s`, then the dashboard (`dashboard.py`) and `ingest_lan.py` for ~45 s each, `bug_outbox --print`, and `mcp_probe.py` against `health_mcp.py` on stdio if it supports that.
- **GHCR image and release assets** (`compose.yaml`, `health.env`, Colima plist) were not downloaded or compared with this source. The bug-receiver URL is baked into release images and is not in the repo.
- **Breadth:** about 1,900 files (1,160 `.py`). The review focused on the installer, Docker/compose generation, network clients, auth, auto-run tooling and the static hits. Many SQL "raw query" semgrep hits and most job modules were not read line by line. Prompt files were not read in full for injection text, but hidden-Unicode and instruction-to-agent greps came back clean apart from the BOM strip.
- **Unread file:** `secrets_paths.py` is hidden by the reviewer's deny rules (`static/unreadable-by-reviewer.txt`). The VM scanners covered it. No symlinks were stripped.
- **macOS-only paths** (osascript Reminders, EventKit, launchd, Colima agent) were checked in code only. Linux VM ≠ macOS, and evasion by malware remains possible in general.
