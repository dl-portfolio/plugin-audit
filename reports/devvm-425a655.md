# devvmhq/devvm — USE WITH PRECAUTIONS
Commit `425a655ef6a31f2eaf17a78f2c4546ded5b4fed1` (source says 0.1.1-rc.1; runtime tested the v0.1.0 release) · audited 2026-11-08 · Go CLI that gives each project its own Lima VM for coding agents, with logins, network tiers and an allowlist proxy

**Bottom line:** I found nothing malicious, and the security design is unusually careful and honestly documented:
- Your real Claude/Codex tokens stay on the Mac; VMs get a placeholder that a host proxy swaps in only for fixed hosts.
- VMs don't get your home folder.
- The VM manager's host process runs inside a macOS sandbox profile.

But it is **2 days old (v0.1.0, one maintainer)**, its host proxy holds your real tokens, and some defaults are loose: VM ports are forwarded to your Mac, and devcontainer commands run automatically. Use it only with the precautions below, and with dedicated tokens rather than your main logins.

## What it can touch on the Mac
- **Reads** `~/.claude.json`, `~/.claude/{settings.json,CLAUDE.md,skills,agents,commands,plugins}` and `~/.codex/auth.json`, but only when you run `devvm agent import`, and copies them into its own store.
- **Writes** `~/.local/{bin,lib,share}/devvm`, `~/.config/devvm`, its own Keychain items, an `Include` line in `~/.ssh/config` (it asks first), and `chflags` locks on the project's `.git`.
- **Network:** a daily update check (GitHub releases feed), a daily tool-version check, and image/tool downloads (SHA-256-pinned). No telemetry found.
- **Inside VMs:** your project folder (read-write) and its own store and tools (read-only).

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Install** (its own `install.sh`): it contacted only `github.com` and `release-assets.githubusercontent.com`, downloaded v0.1.0, verified the checksum and installed into `~/.local`. No sudo, no shell-startup edits.
- **Run** (`--help`, `version`, `doctor`, main flow, `agent import claude`, `ls`): no network attempts, no decoy credentials read, no persistence, nothing left running. `agent import claude` checked `~/.claude`, found no settings and imported nothing. No VM could be created (no Lima/KVM inside the test VM).

## How to use it safely
1. Install via Homebrew (`devvmhq/tap`), or `install.sh` with `minisign` installed, and check the signature against the key in the README.
2. Run `devvm ports none` (or choose ports per VM); turn off VS Code's automatic port forwarding.
3. For untrusted repos use `--no-devcontainer` and `--clone`, and the `allowlist` or `none` network tier. Never `open`.
4. Don't `devvm agent import` your main Claude/GitHub logins. Use a dedicated `claude setup-token` and a fine-grained, repo-scoped GitHub token, bound only to VMs that need it.
5. Leave SSH agent forwarding off. Don't start VMs with `devvm limactl` (that bypasses its macOS sandbox profile).
6. Review files a VM wrote before running them on the Mac.
7. It's very new: pin to a release, and re-run `/audit` before upgrading.
