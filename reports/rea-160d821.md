# morluto/rea — USE WITH PRECAUTIONS
Commit `160d821ac9a0310afcb8d1fc427862dd6508add5` (npm `rea-agents` 6.8.0) · audited 2026-11-09 · "Reverse Engineer Anything": a Node CLI and MCP server (~190 commands) that lets an AI agent decompile, inspect and runtime-observe binaries, apps, APKs, firmware, browser pages and captures. Ghidra, Hopper, IDA, JADX, Frida and similar engines plug in as providers. It ships an agent skill (`reverse-engineer-anything`).

**Bottom line:** No malware, telemetry, phone-home, obfuscation or hidden agent instructions were found. Every high or critical scanner hit traced to test fixtures, maintainer scripts or analysis features. The risk comes from what the tool is for. Its runtime tools **launch, debug and instrument the target** (unrestricted GDB and Rizin commands, Frida scripts, LLDB, process and Electron capture, adb install/push). The bundled skill tells agents to call them without per-call approval and to fetch `npx -y rea-agents@latest`. Use it on samples you trust, or inside a VM, and pin the version. **The VM run only built the source checkout and printed `--help`/`--version`.** `rea setup`, the MCP server and every analysis command went unexercised, so this verdict rests mainly on code review.

## What it can touch
- **Files:** reads the paths and artifacts you or the agent name, and writes only to output directories you choose. Analysis results are stored by REA in its cache.
- **Agent config (only via `rea setup`):** adds an MCP entry to the chosen client's config (e.g. `~/.claude.json`) and copies the skill into e.g. `~/.claude/skills/reverse-engineer-anything`. It shows a plan, asks for approval or `--yes`, makes backups, and only adds entries. It writes no hooks and grants no permissions. `rea uninstall` removes what it added.
- **Network (on demand):** `api.github.com` (latest release lookup in `install.sh`), the npm registry (`rea update`, `npx`), and `www.hopperapp.com` for the optional Hopper install. That download is PGP-checked against a pinned fingerprint. Browser and web tools contact the pages you point them at. It has no telemetry or analytics code.
- **Processes:** runs the engines you configure (Ghidra/Java, Hopper, IDA MCP, Rizin, GDB, LLDB, Frida, tshark, apktool, adb, Playwright/Chromium). Runtime tools **execute the target**.
- **Credentials:** none needed. It reads only `NODE_OPTIONS` from `/proc/self/environ` (`src/process/RegexMatcher.ts:244-255`).
- **Listening ports:** only `environment-serve` (streamable HTTP, Host-header allowlist when bound to loopback, `src/server/http/serveStreamableHttp.ts:99-108`). The default MCP transport is stdio.
- **Persistence / auto-run:** none for users. `npm prepare` only patches release-please and installs husky git hooks in a dev checkout (`scripts/prepare.mjs:26-39`). `rea update` runs only when you call it, and uses `--ignore-scripts` (`src/application/Update.ts:94-106`).

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Install** (`npm ci` + `npm run build` of the source checkout, 58 s, exit 0): `registry.npmjs.org` ×15, `github.com` and `release-assets.githubusercontent.com` ×1 each (prebuilt binary). The only refused host was **`telemetry.vercel.com` ×3, from the `turbo` dev build tool**, not REA. `turbo` also wrote `~/.config/turborepo/telemetry.json`. Decoy reads: `~/.npmrc` ×5 by npm (expected). There were no unexpected credential reads, direct egress, suspicious execs or persistence.
- **Run** (`rea --help`/`--version` ×2, 6 s): no DNS, no connections, no decoy reads, no file changes, no leftover processes. It printed version `6.8.0` and the command list.
- **Agent config:** the planted `~/.claude/settings.json` and `~/.claude.json` were unchanged after the run, because `setup` was never called.

## How to use it safely
1. **Pin the version:** `npm install -g rea-agents@6.8.0` (or `npx -y rea-agents@6.8.0 setup`). Don't run `install.sh` without `--version 6.8.0`. Re-audit before `rea update`.
2. Run `rea setup --client claude_code --dry-run` first, review the paths and backups, then apply. Skip `--install-hopper` unless you need it.
3. **Pin the skill too:** after setup, edit the installed `SKILL.md` and replace `rea-agents@latest` with `rea-agents@6.8.0`, or tell the agent to use the installed `rea` CLI. Otherwise the agent may fetch newer releases on its own.
4. **Keep REA's MCP tools on "ask"** in Claude Code, especially `debug_with_gdb`, `debug_with_rizin`, `instrument_with_frida`, `capture_*`, `observe_native_calls`, `install_adb_package`/`push_adb_file`, `start_adb_*` and `environment_serve`.
5. **Analyze untrusted or suspected-malicious samples only in a VM.** Static inspection still parses hostile bytes, and runtime tools execute them. On the Mac, use it on your own builds and trusted apps.
6. Don't connect a personal phone over adb while an agent drives REA. Use a test device or emulator.
7. Run `environment-serve` only on loopback, and stop it when you're done.

## Not covered
- **Not exercised at runtime by the auto scenario:** `install.sh` / `npx rea-agents setup` (the documented install path, which fetches from npm and edits agent config), `rea setup` and `doctor` against the planted configs, the MCP server (no `mcp_probe.py` run), every analysis command on a sample file, the browser/Electron/process capture and debugger tools, `rea update`, the Hopper download, and `environment-serve`. A useful re-run: install.sh `npm ci && npm run build:cached`; run.sh `node scripts/rea.mjs setup --client claude_code --dry-run --json`, then `--yes` and print the configs, `mcp_probe.py --call -- node scripts/rea.mjs mcp`, `inspect-artifact` / `inspect-byte-entropy` / `analyze-javascript-application` on small samples, and `doctor --json`.
- **The npm tarball was not compared with this source.** Users who run `npx rea-agents` get the registry build, not this checkout.
- **Partial code review:** 6,280 files (4,779 `.ts`). I reviewed install, setup, update, release downloads, network endpoints, the skill and every flagged hit. I did not read every parser or the Ghidra/Hopper/IDA/Cutter bridges line by line. Third-party engines were not reviewed.
- **Linux VM ≠ macOS:** the Hopper, LLDB, native-UI and Apple bundle paths are macOS-specific and were checked only in code. Evasion by malware remains possible in general.
- **Unread files:** none hidden by deny rules (`static/unreadable-by-reviewer.txt` is empty). 2 large files were skipped by our checks, and 1 binary file can't be read as source. The Windows native addon `rea-windows-x64.node` listed in `package.json#files` is not in the repo. It is built at release time, and that release artifact was not audited.
