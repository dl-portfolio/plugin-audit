# rtk-ai/rtk — USE WITH PRECAUTIONS
Commit `e288a18c04452fd26192f59132e5324a8bb6924d` (v1.2.0) · audited 2026-11-09 · Rust CLI wrapper that shrinks command output before an AI agent reads it. Installs a Claude Code hook that rewrites every Bash command to `rtk <cmd>`. Includes an optional local LLM API proxy.

**Bottom line:** No malware, phone-home or hidden instructions were found. Telemetry is off unless you explicitly opt in. The risk is in where rtk sits: once `rtk init -g` runs, the rtk binary is in the path of every shell command Claude runs. So install it pinned, from a source you trust, and treat updates as re-audits. **The VM run did not exercise rtk at all** (no Rust toolchain, and the auto scenario ran only a placeholder). This verdict rests on code review only.

## What it can touch
- **Files:** `~/.claude/settings.json` (PreToolUse hook, keeps a `.json.bak` backup), `~/.claude/RTK.md` plus an `@RTK.md` line in `~/.claude/CLAUDE.md`, and its own config and data (`~/.config/rtk/`, `~/.local/share/rtk/`, created with private permissions). `rtk discover` reads `~/.claude/projects/*.jsonl` locally.
- **Processes:** runs the command it wraps (git, cargo, npm …). The hook binary `rtk` is called for every Bash tool call.
- **Network (CLI):** nothing by default. Opt-in telemetry goes to a URL compiled into release builds. `rtk pipeline add` fetches from GitHub, a gist or any URL you give it. Pipeline LLM tasks call the upstreams you configure (e.g. Gemini, Anthropic).
- **Network (optional `rtk-proxy`):** listens on `127.0.0.1:8080` and forwards your agent's API traffic, including the API key, to `api.anthropic.com` / `api.openai.com` or whatever upstream is set.
- **Credentials:** none read by default. A pipeline you write yourself may use `api_key_env` or `api_key_command` (e.g. a Keychain lookup).
- **Persistence (opt-in only):** a SessionStart hook or a launchd user agent (`~/Library/LaunchAgents`) that keeps the proxy running. You are only asked about this if you agree to set up the proxy.

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Install:** the auto scenario only wrote a sample `~/.claude/settings.json` and `~/.claude.json`. rtk was **not** built or installed: there is no Rust toolchain in the VM, and the repo's `install.sh` was not run because it downloads from GitHub.
- **Run:** only `cat` on those two files. No rtk process ran.
- **Results:** 0 decoy reads, 0 DNS lookups, 0 connections, no persistence, no leftover processes. These are **meaningless as evidence about rtk** because none of its code ran.

## How to use it safely
1. Install a pinned version: `RTK_VERSION=v1.2.0 sh install.sh` from a reviewed copy, or `cargo install --git https://github.com/rtk-ai/rtk --rev e288a18 rtk` (builds from the audited source). Avoid `curl … | sh` from `master`.
2. Run `rtk init -g` interactively and read the diff it proposes. Keep `~/.claude/settings.json.bak`. Undo with `rtk init -g --uninstall`.
3. Answer **N** to the proxy question unless you need it. If you use it, keep the loopback bind, don't install the background service, and run `rtk llm-proxy stop` when you're done.
4. Don't add third-party pipelines (`rtk pipeline add`). Use only built-in or self-written ones, and pin by commit SHA (`github:owner/repo@<40-hex>`).
5. Leave telemetry off (the default). Don't enable `tee_on_success` or `RTK_HOOK_AUDIT` in repos where command lines carry secrets.
6. Treat every rtk update as a new audit: it runs on every agent command.
