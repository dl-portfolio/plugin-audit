# apache/maka — USE WITH PRECAUTIONS
Commit `b511478d0a01d2a20437a56cd435ab71a6cb2815` (0.2.2 incubating) · audited 2026-11-09 · Apache-incubating AI agent harness: an Electron desktop app plus TUI/CLI around one "Runtime Host" that runs models (cloud API, local model or subscription login) with shell, file, web, MCP, computer-use and chat-bot tools.

**Bottom line:** No malware, phone-home, analytics SDK or hidden instructions were found. Install hooks only patch dependencies and download Electron, and the VM install matched that. The risk is what it is built to do: an LLM agent with shell and file access under your account, API keys and subscription tokens kept in a plaintext file, and optional remote-control channels (chat bots, remote/peer Host). Use it with the default `ask` mode, keep bots and remote access off unless you need them, and set a bot allowlist if you turn one on. **The VM run never started Maka.** The auto scenario only installed and built it, so the verdict rests on code review for everything after install.

## What it can touch
- **Files:** your workspace/project folders (agent `Read`/`Write`/`Edit`/`Bash`). Its own data lives under Electron `userData/workspaces/default/` (SQLite log, settings, `credentials.json`/`credential-vault.json` stored as plaintext with 0600 permissions). It reads skills from the standard Agent Skills folders and reads `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` in workspaces as instructions.
- **Processes:** agent Bash (macOS: wrapped in `sandbox-exec` Seatbelt in `ask`/`explore` modes; no sandbox in bypass/unrestricted), PTY terminals, MCP servers you add, ACP agents (external coding CLIs), `gh auth token` (only when you click "import existing GitHub login"), `ssh` for remote Hosts, macOS computer-use (screen and input control).
- **Network:** the model providers you configure (~40 known endpoints in `packages/core/src/provider-registry.ts`), Tavily web search, OAuth (OpenAI/Codex, GitHub Copilot, xAI, Claude), bot platforms you enable (Telegram, Discord, Slack, QQ, WeChat, DingTalk, Feishu), GitHub Releases for app updates (packaged builds only). Experimental peer mode uses the public IPFS DHT for relays and Cloudflare STUN.
- **Listeners:** a local IPC socket and a loopback WebSocket by default. `0.0.0.0` only if you pass `--websocket-host` with TLS or acknowledged plaintext.
- **Credentials:** keys and tokens you enter. Optionally imports `COPILOT_GITHUB_TOKEN`/`GH_TOKEN`/`GITHUB_TOKEN` or `gh auth token`, only on your action.
- **Persistence:** none by default. `maka runtime-host` can install a user service for a persistent Host if you ask it to.

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Install (`npm ci` + `npm run build`, 91 s, exit 0):** 982 packages. The patches applied cleanly and all 12 workspaces built (tsc, esbuild, vite). Hosts: `registry.npmjs.org`, plus `github.com` → `release-assets.githubusercontent.com` once (the Electron binary). No refused hosts, no direct egress, no suspicious execs. 23 decoy reads, all of `~/.npmrc` by npm (expected). No persistence and no leftover processes. The only new home files were the planted `~/.claude*` samples, unchanged.
- **Run:** the auto `run.sh` only printed the planted `~/.claude/settings.json` and `~/.claude.json` (2 s). `notes.txt` says bins were called with `--help`, **but they were not**. No Maka code ran, so 0 DNS, 0 connections and 0 decoy reads in this phase say nothing about Maka itself.

## How to use it safely
1. Build from the signed Apache source release or this commit (`b511478`), with `npm ci` (lockfile). Treat later commits and nightly builds as unaudited.
2. Keep the per-session mode on `ask` (default) or `explore`. Avoid `bypass`/unrestricted profiles, and don't let the agent drive the integrated terminal on untrusted content.
3. Open only workspaces you trust: their `AGENTS.md`/`CLAUDE.md` and skills become agent instructions.
4. Leave bots off. If you enable one, set `allowedUserIds` to your own ID before connecting the token.
5. Keep the Runtime Host on loopback/SSH. Don't use plaintext `--websocket-host 0.0.0.0` or experimental peer mode unless you need them.
6. Use dedicated, spend-limited API keys. Assume `credentials.json` is readable by any process running as your user, and exclude the `userData` folder from cloud-synced backups.
7. Don't enable computer-use (screen and input control) unless you need it, and grant macOS Accessibility/Screen Recording only to the Maka app.
8. Keep Electron current: re-audit when upgrading, given the 8 open Electron advisories at this commit.

- **Unread file:** `apps/desktop/src/main/web-search/credentials.ts` is hidden by your deny rules and was not read (scanners still covered it). Run `./audit.sh copies maka-b511478` to include it. No symlinks were stripped.
