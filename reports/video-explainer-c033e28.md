# prajwal-y/video_explainer — USE WITH PRECAUTIONS
Commit `c033e28d6eccae43c1762f4653f9c320b16b050e` (video-explainer 0.1.0) · audited 2026-11-09 · Python CLI (`video-explainer` / `python -m src.cli`) that turns documents, PDFs or URLs into explainer videos. It writes scripts and Remotion (React) scenes by running the **Claude Code CLI** headless, then renders with a bundled Remotion project (`remotion/`, npm).

**Bottom line:** We found no malware, telemetry, obfuscation, persistence or hidden instructions. The risk is in its design. With the default config (`llm.provider: claude-code`), it runs `claude --dangerously-skip-permissions` with **Bash, Write and Edit** to write scene code. The `refine` visual phase goes further: `claude --chrome --dangerously-skip-permissions` with **all tools and your real Chrome**. These prompts are built from the documents or URLs you feed it, so a prompt-injected source could run shell commands or browse as you, with no permission prompt. Only run it on sources you trust, ideally in a VM or container. **The VM run only installed the Python package and printed `--help`.** No pipeline step, npm install, Claude call or render ran, so the verdict rests on code review.

## What it can touch
- **Processes:** `claude` CLI (headless, permissions skipped when tools are granted), `npm run dev` (Remotion studio on `localhost:3000`), `ffmpeg`, `$EDITOR`. All are list-argument calls with no shell strings.
- **Claude Code:** runs `claude` from the repo root (it loads the repo's `.claude/skills/remotion`, a copy of the Remotion docs skill). With `--chrome` it drives your logged-in Chrome through the Claude in Chrome extension. It **does not edit** `~/.claude` or any agent config.
- **Files:** its own `projects/<id>/` and `remotion/` folders. The Claude subprocess with Bash can reach anything your user can.
- **Network (on demand):** any URL you ingest (`httpx`, follows redirects). `api.elevenlabs.io` (TTS, `ELEVENLABS_API_KEY`). Microsoft Edge TTS service (`edge-tts`). Hugging Face model download for `music` (MusicGen, optional `transformers`). Whisper model download (optional extra). Anthropic, through the `claude` CLI.
- **Credentials:** reads only `ELEVENLABS_API_KEY` from the environment. The README also lists `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`, but those providers raise `NotImplementedError` (`src/understanding/llm_provider.py:782-785`). Only your Claude Code login is used.
- **Persistence / auto-run:** none. No install hooks, Claude hooks, MCP server or auto-update.

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Install** (auto scenario: `uv venv` + `uv pip install -e .`): 14 s, exit 0. Contacted only `pypi.org` and `files.pythonhosted.org` through the proxy. No refused hosts, no direct egress, 0 decoy reads. Home reads were only uv config probes and the planted `~/.claude` files (read by the scenario's own `bash`, not the tool).
- **Run:** `video-explainer --help` printed the 17 subcommands. `--version` is not supported (argparse error). 2 s, 0 DNS lookups, 0 connections, 0 decoy reads.
- **Persistence:** none. No startup files, cron, autostart or new executables. No leftover processes. The only new files were the two config files the scenario planted, unchanged.

## How to use it safely
1. Pin it: clone at commit `c033e28` and install in a venv. Consider `uv pip compile pyproject.toml` to freeze Python deps. Install the npm side with `npm ci` (uses the lockfile), not `npm install`.
2. **Run the pipeline in a VM, devcontainer or throwaway user account**, not your main macOS user, because it hands Claude Code Bash with prompts disabled. If you must run it on the Mac, use a separate Claude Code login with no access to sensitive repos.
3. **Only feed it sources you trust** (your own docs, known-good pages). Treat any URL or PDF as able to run commands through the generated prompts.
4. **Don't run `refine` with the default visual phase in your normal Chrome profile.** Either skip it, use a separate Chrome profile signed in to nothing, or run it inside the VM.
5. Before rendering, review the Claude-written diffs in `projects/<id>/scenes/` (`git diff`), since that code executes under Remotion.
6. Leave ElevenLabs off unless you need it (the shipped `config.yaml` uses `tts.provider: mock`). Use a dedicated, revocable API key.
7. Ignore the Dockerfile (broken, `curl | bash`). Re-audit before updating.

## Not covered
- **Most of the tool did not run.** The auto scenario never ran `cd remotion && npm install` (README step), `create`/`generate`/`script`/`scenes`/`refine`, URL/PDF ingestion, TTS (ElevenLabs/Edge), `music` (MusicGen/Hugging Face), Whisper, the Remotion studio or `render`. No `claude` CLI or Chrome exists in the VM, so the headless Claude calls (the main risk) were reviewed in code only. A useful re-run: install.sh adds `cd remotion && npm ci`. run.sh runs `video-explainer create demo`, then `script`/`storyboard` with `llm.provider: mock` on a small local Markdown file, and starts `npm run dev` for ~45 s.
- **npm dependency tree** (Remotion, three.js, webpack …) was checked by OSV only, not reviewed. PyPI wheels were not compared with source.
- **Large surface:** 172 Python files. We reviewed every subprocess, network, env, file-path and Claude-invocation site, but not every prompt template line by line.
- **Linux VM ≠ macOS**, and evasion by malware remains possible in general.
- **Unread files:** none hidden by deny rules (`static/unreadable-by-reviewer.txt` is empty). No symlinks were stripped.
