# mattpocock/skills — USE WITH PRECAUTIONS
Commit `d1478fcb140db0b93c0c8df17bcfd311844749d0` (v1.3.2) · audited 2026-11-09 · Claude Code / Codex / Copilot plugin with 27 prompt-only engineering and productivity skills (grilling, spec → tickets → implement, TDD, code review, triage, debugging), plus unshipped `misc/` and `in-progress/` skills

**Bottom line:** No malware, no phone-home and no hidden instructions. The shipped plugin is Markdown prompts only, with no hooks, MCP servers, tool grants or install scripts. The precautions come from a few skills, all of which you have to start yourself:
- `/triage` tells the agent to check out and run the code in outside pull requests (off by default), to reproduce bugs from reporters' steps, and to comment on, label and close issues with `gh`.
- `/implement-spec` runs background subagents that commit and merge.
- The documented install updates itself from `main`.

Use it with normal permission prompts on, pin the version, and run triage of outside contributions in a sandbox.

## What it can touch
- **Files:** only through your agent's normal permissions. Skills write `GLOSSARY.md`, ADRs, `docs/agents/*.md`, `.scratch/` tickets, and handoff docs or HTML reports in `$TMPDIR`. `setup-matt-pocock-skills` edits the `## Agent skills` block of your repo's `CLAUDE.md`/`AGENTS.md`, and only after you approve a draft. `retro` reads your agent session logs. `wizard` reads `.env*` files and writes captured values to `.env` (mode 0600 when it creates the file).
- **Git / GitHub:** `gh`/`glab` issue create/comment/label/close and `gh label create`. `setup-*` may run `git init` and `git remote add`. `implement`/`implement-spec` commit, create worktrees and merge into an integration branch. `wizard` scripts set GitHub Actions secrets via `gh secret set`. Nothing pushes or force-pushes on its own.
- **Network:** the plugin itself makes no network calls. The `improve-codebase-architecture` HTML report loads Tailwind (`cdn.tailwindcss.com`) and Mermaid (`cdn.jsdelivr.net`, `mermaid@11`, unpinned minor version) in your browser. `research` uses the agent's web access.
- **Claude config / credentials / startup files:** none in the shipped plugin. Only the unshipped `misc/git-guardrails-claude-code` (adds a hook to `settings.json` when you ask it to) and the maintainer script `scripts/link-skills.sh` (symlinks into `~/.claude/skills` and `~/.agents/skills`) touch Claude config.

## Runtime behaviour (VM, decoy credentials, network blocked)
- **Scenario:** the auto-generated one, which was not adapted to this target. Install planted a fake `~/.claude/settings.json` and `~/.claude.json`, then ran `npm ci` on the repo's dev dependencies (changesets release tooling). Run only printed those two config files.
- **Install:** contacted only `registry.npmjs.org` (15 requests via the proxy, no refused hosts, no direct egress). The only decoy read was `~/.npmrc` by npm itself (expected). No suspicious execs, no persistence, no leftover processes. The only new files outside the project were the two planted configs.
- **Run:** no network, DNS, decoy reads or file changes.
- **What it did not exercise:** the documented installs (`claude plugin install …@claude-plugins-official`, `codex`/`copilot plugin`, `gemini skills install`, `npx skills@latest add`). Also not exercised: any skill running inside an agent session, the `git-guardrails` hook (`fire_hooks.py` was not used), `scripts/link-skills.sh`, the `wizard` and `hitl-loop` templates, and `sync-plugin-version.mjs`. The notes say "bins called with --help", but there are no bins and `run.sh` called none. So the clean runtime result only covers `npm ci` of maintainer tooling. The verdict rests on the code review. That is adequate here: the plugin is prompt text, and every shell/JS file (5 `.sh`, 1 `.mjs`, 1 `.cjs` config) is short and was read in full.

## How to use it safely
1. Install only the Claude Code plugin (`claude plugin install mattpocock-skills@claude-plugins-official`), which ships just the 27 `engineering/` + `productivity/` skills. Don't also run `npx skills add` (you'd get duplicates and the option to pull in the beta skills).
2. Turn off auto-update for this plugin, or re-audit before moving past `d1478fc`. Don't add the Copilot `autoUpdate: true` snippet.
3. Keep Claude Code permission prompts on (no `--dangerously-skip-permissions`), especially for `/implement-spec`, `/triage` and `/wizard`, which run `git`, `gh` and shell commands.
4. `/triage`: leave the "PRs as a request surface" flag **off**. If you triage outside contributors, run it in a container/VM without your credentials. Approve each repro command, comment and close yourself.
5. Run `/wizard` scripts yourself after reading them, and make sure `.env` is in `.gitignore`. Use `/retro` only if you are fine with the agent reading past session transcripts.
6. Don't run `scripts/link-skills.sh` (it is for the maintainer and deletes same-named skill folders). Don't treat `git-guardrails-claude-code` as a security boundary.
